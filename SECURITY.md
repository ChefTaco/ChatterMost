# Security reports

Do not publish exploit details, credentials, live endpoints, user data, or private deployment evidence in public issues.

Use the repository hosting service's private vulnerability-reporting feature when the maintainer has enabled it. If private reporting is unavailable, open a minimal issue asking the maintainer for a private contact channel without including sensitive details. Operators should rotate compromised credentials using the documented rotation workflows and preserve evidence privately.

Include affected versions, a synthetic reproduction, expected behavior, and impact in the private report. Review attachments using [PRIVACY.md](PRIVACY.md) before sharing them.
